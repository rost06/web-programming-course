# Учебный тренажёр: TypeScript и React

За первое полугодие вы создадите приложение для прохождения учебных заданий. На итоговом тестировании сможете использовать свой интерфейс. Во втором полугодии проект продолжится.

## Занятия

| Лекция | Самостоятельная работа после лекции | Сдача |
| --- | --- | --- |
| [L1. TypeScript и данные](../lessons/l1/README.md) | Модель и функции обработки данных | P2 |
| [L2. Компоненты React](../lessons/l2/README.md) | Каталог и отображение заданий | P3 |

| [L5. HTTP и сервер](../lessons/l5/README.md) | Подключение к учебному API | P6 |
| [L6. Проверка приложения](../lessons/l6/README.md) | Тесты поведения | P7 |

На практике в день новой лекции проверяется работа, выданная на предыдущей лекции. Первая практика проверяет стартовое задание ознакомительной встречи. Между обычными встречами — две недели; вторая группа приходит на практику через два дня после первой. Срок PR — перед своей следующей практикой, точное время сообщает преподаватель.

## Сдача

Работайте в своём форке. Для L1 после синхронизации создайте ветку от актуального `main`. Для L2 и следующих этапов создавайте новую ветку от предыдущей рабочей версии или сохранённого SHA точки сдачи: так код A1, A2 и следующих этапов остаётся в истории, даже если предыдущий PR ещё не завершён. Сохраняйте изменения коммитами и открывайте PR в репозиторий курса. В названии укажите номер задания; в описании — основание ветки, что выполнено, как проверить и какие ограничения остались. Сохраните идентификатор коммита сдачи (`git rev-parse HEAD`), чтобы отличать этот результат от следующих изменений.

Если PR содержит предыдущие этапы, укажите предыдущий PR и коммит: новая проверка относится к изменению текущего этапа. Не нужно сливать незавершённый PR в `main`, чтобы продолжить проект от своей рабочей версии. Доработки оформляйте новыми коммитами и отмечайте, какое замечание исправлено.

На проверке покажите поведение программы и соответствующий код, ответьте на вопросы по пройденной теме. Критерии каждого задания опубликованы заранее. Материал новой лекции не добавляет требований к уже сдаваемой работе.

Итоговое тестирование проверяет знания, а проверка проекта — реализацию и понимание своего кода. При техническом сбое преподаватель предоставляет резервный интерфейс для прохождения теста.
