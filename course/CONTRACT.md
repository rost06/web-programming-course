# Данные и API учебного тренажёра

Версия формата: 1. Контракт одинаков для всех этапов курса. [Учебный набор](data/training-set.json).

## Набор и задания

Набор содержит `id`, `title`, `tasks`. Каждое задание: `id`, `kind`, `topic`, `prompt`, необязательный `code`. У `single-choice` есть `options`, массив объектов `{id,label}`. У `short-text` вариантов нет. Идентификаторы уникальны в наборе и не зависят от порядка отображения. Строки `code` показываются как текст, не исполняются.

Студент самостоятельно описывает эти данные средствами TS на L1. `kind` имеет два значения: `single-choice` и `short-text`.

Ответ имеет один из форматов:

```json
{"taskId":"ts-1","kind":"single-choice","optionId":"b"}
```

```json
{"taskId":"react-1","kind":"short-text","text":"Моё объяснение"}
```

Пустая строка и строка только из пробелов считаются отсутствием текстового ответа. Перед отправкой клиент проверяет заполненность. Сервер проверяет тип, принадлежность задания набору и optionId списку вариантов. Для очистки уже сохранённого ответа предусмотрен DELETE.

## Локальный сервер

Из корня репозитория, Linux и Windows PowerShell:

```sh
node course/server/server.mjs
```

Адрес `http://localhost:3001`. Сервер предоставлен преподавателем для A5–A6. Хранение попыток в памяти: перезапуск сервера удаляет их. Перезагрузка браузера при работающем сервере данные сохраняет. Учебный сервер не проверяет личность пользователя и не предназначен для официального тестирования.

## Маршруты

| Метод и путь | Тело запроса | Ответ |
| --- | --- | --- |
| GET /api/sets | — | `[{id,title,taskCount}]` |
| GET /api/sets/:id | — | `{id,title,tasks}` |
| POST /api/attempts | `{setId}` | 201, Attempt |
| GET /api/attempts/:id | — | 200, Attempt |
| PUT /api/attempts/:id/answers/:taskId | Answer, taskId совпадает с путём | 200, Attempt |
| DELETE /api/attempts/:id/answers/:taskId | — | 200, Attempt |
| POST /api/attempts/:id/submit | `{}` | 200, Result |
| GET /api/attempts/:id/result | — | 200, Result; 409 до завершения |

`Attempt`: `{id,setId,status,answers}`; status `in-progress` или `submitted`; answers — массив Answer. PUT заменяет ответ этого taskId. DELETE удаляет его; повторное удаление допустимо. После submit изменение ответов возвращает 409. Повторный submit возвращает тот же результат, а не создаёт новую попытку.

`Result`: `{attemptId,status,score,maxScore,items}`; status `graded` или `pending-review`. Каждый item: `{taskId,status,score,maxScore,feedback}`, status `correct`, `incorrect`, `unanswered` или `pending-review`. score у ожидающего проверки ответа и у общего результата с ожидающими ответами равен `null`. maxScore — число заданий, по одному баллу за каждое. Пропущенный ответ получает 0; непустой short-text ожидает ручной проверки. Интерфейс показывает ожидание, не подменяет null нулём. Учебный сервер не предоставляет интерфейс ручного оценивания.

Ошибки: `{error:{code,message}}`; 400 — неверное тело, 404 — объект не найден, 409 — действие не соответствует состоянию, 413 — слишком большое тело, 500 — искусственная учебная ошибка. Клиент проверяет `response.ok`: HTTP 400/500 сами по себе не отклоняют Promise fetch.

Для демонстрации ошибки добавьте к любому API-запросу заголовок `X-Demo-Fail: 1`: сервер вернёт 500 без изменения данных. При повторе уберите заголовок. Этот механизм существует только в учебном сервере.

## Черновик и восстановление

Локальный черновик A4: `{version:1,setId,taskId,answers,status}`, status `in-progress` или `submitted`. Приложение проверяет формат и setId. При несовместимости предлагает явный сброс, не теряет данные молча. На A5 можно добавить `attemptId` и хранить неподтверждённые ответы отдельно. Серверные подтверждённые ответы являются основой; локальное изменение не выдаётся за сохранённое на сервере.

## Учебный и контрольный режимы

Учебный сервер и его открытые данные используются при разработке. Официальные ключи и банк не входят в этот пакет. Для аттестации преподаватель предоставляет совместимый сервер, доступ участника и резервный интерфейс; менять способ доступа без отдельной инструкции не требуется. Клиент никогда не отправляет вычисленную им оценку как результат тестирования.
