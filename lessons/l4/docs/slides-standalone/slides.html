L4 · черновик и границы состояния

Восстановить, но не выдумать

Reducer делает переходы явными, эффект синхронизирует состояние с браузером.

Почему A3 нужно укрепить

  • Обновление уничтожает память React.
  • Разбросанные обработчики усложняют правила.
  • Чужой JSON нельзя принимать вслепую.

Reducer: события

dispatch({ type: "answerChanged", answer: next })

Компонент сообщает событие, reducer решает новое состояние.

Reducer должен быть чистым

Одинаковые state и action дают одинаковый результат. Внутри нет localStorage, fetch, таймера, случайности и мутации.

Эффект — граница

useEffect(() => localStorage.setItem(key, JSON.stringify(draft)), [key, draft])

Синхронизация выполняется после отображения.

Формат черновика

{ version: 1, setId, taskId, answers, status }

Версия — миграция формата, setId — защита от чужого набора.

JSON не равен типу

  1. Получить строку или null.
  2. Перехватить ошибку parse.
  3. Проверить unknown.
  4. Проверить все поля ответов.

Несовместимость видна

«Нет черновика» и «черновик повреждён» — разные состояния. Сообщите причину и дайте явный сброс.

Хранилище может отказать

Квота или приватный режим могут бросить исключение. Ввод продолжается в памяти, пользователь видит предупреждение.

Завершённая попытка

submitted можно показать, но нельзя восстановить как редактируемую. Новая попытка — отдельное явное действие.

Демонстрация четырёх отказов

  1. Ответить и обновить.
  2. Записать {.
  3. Подменить setId.
  4. Продолжить ввод при отказе записи.
