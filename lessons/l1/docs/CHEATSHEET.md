## Зачем

TypeScript описывает форму данных до запуска, а чистые функции позволяют отдельно проверить поиск, фильтрацию и производные значения. На L1 вы создаёте проект `trainer` самостоятельно; исходные файлы задания пишутся вами.

## Инструменты проекта

| Элемент | Роль |
| --- | --- |
| `package.json` | имя проекта, зависимости и `scripts` |
| `package-lock.json` | точные версии дерева зависимостей |
| `node_modules/` | локально установленные пакеты, не коммитить |
| `tsconfig.json` | правила компилятора TypeScript |
| `check` | проверка типов без вывода файлов |
| `demo` | запуск `src/demo.ts` через `tsx` |

Подробная последовательность создания проекта находится в [гайде](GUIDE.md). После появления своих `package.json` и lockfile, из `trainer/`, одинаково в Linux и Windows PowerShell:

```sh
npm run check
npm run demo
```

TypeScript устанавливайте точно: `npm view typescript@5.8.3 version`, затем `npm install typescript@5.8.3 tsx@4.23.13 --save-dev --save-exact`. Не используйте `typescript@latest`, `*` или незафиксированный диапазон. Для чистой повторной установки после появления lockfile используйте `npm ci`.

Минимальные параметры `tsconfig.json`: `target: "ES2022"`, `module: "ESNext"`, `moduleResolution: "Bundler"`, `strict: true`, `skipLibCheck: true`, `resolveJsonModule: true`, `noEmit: true`, `include: ["src"]`.

## Модель

- общие поля вынесены в понятную модель;
- разные формы данных различаются литеральным полем (`kind`);
- `single-choice` имеет варианты, `short-text` — текст;
- ответ связывается с заданием через `taskId`;
- `topic` остаётся произвольной строкой;
- строка из внешних пробелов не считается заполненной;
- `code` — данные для показа, не исполняемый код.

## Коллекции

| Операция | Результат | Что проверить |
| --- | --- | --- |
| `find` | элемент или `undefined` | ветку отсутствия |
| `filter` | новый массив, возможно пустой | исходный массив не изменился |
| `trim` | строка без внешних пробелов | пустой результат |
| производный прогресс | заполнено / всего | чужой id не учитывается |

Названия функций и точный формат прогресса выберите сами. Не используйте индекс массива как идентификатор и не добавляйте `any` или необоснованное `as`.

## Демонстрация A1

В `src/demo.ts` нужны типизированные литералы для двух заданий `ts-1` и `react-1`, массивы ответов, второй набор с другими id и темой и пустой набор. Покажите обычные и пустые случаи, неизвестный id, чужой `taskId` и неизменность входов. Повреждённые внешние объекты в A1 проверять не требуется.

```sh
npm run check
npm run demo
```

До L2 не добавляйте React, Vite, HTTP, формы и хранилище.
