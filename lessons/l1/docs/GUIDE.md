# Гайд L1: как начать TypeScript-проект и описать данные

[Задание](../README.md) · [Гайд](GUIDE.md) · [Справка](CHEATSHEET.md) · [Интерактив](interactive.html) · [Слайды](slides-standalone/slides.html)

## Зачем эта тема

L1 отделяет данные приложения от будущего интерфейса. Типы фиксируют договорённость о форме значения, функции коллекций отвечают за небольшие правила, а чистые функции можно проверить без браузера и сервера. Рабочую точку и доменную модель A1 вы создаёте самостоятельно.

## Термины до первой команды

- **пакет** — опубликованный модуль, который проект может использовать;
- **npm** — менеджер пакетов и команд проекта;
- **`package.json`** — манифест с именем, зависимостями и `scripts`;
- **`package-lock.json`** — зафиксированное дерево точных версий;
- **`node_modules/`** — локальная установка пакетов, её не коммитят;
- **`tsconfig.json`** — правила компилятора TypeScript;
- **check** — команда, которая проверяет типы;
- **demo** — команда, которая запускает TypeScript-файл.

Понимание этих ролей помогает отличить настройку инструмента от кода задания. `npm` не является заменой TypeScript, а успешный запуск файла не доказывает, что все типы и сценарии A1 проверены.

## Создайте минимальную инфраструктуру

В корне репозитория откройте папку `trainer/`. Она содержит только README и `.gitignore`, поэтому проект создаётся с нуля:

```sh
cd trainer
npm init -y
npm pkg set private=true --json
npm pkg set type=module
npm view typescript@5.8.3 version
npm install typescript@5.8.3 tsx@4.23.13 --save-dev --save-exact
npm pkg set "scripts.check=tsc --noEmit" "scripts.demo=tsx src/demo.ts"
mkdir src
```

`npm view` — проверка источника версии в реестре npm. Ожидайте `5.8.3`; используйте точную запись `typescript@5.8.3`, а не `latest`, `*` или незафиксированный диапазон. Флаг `--save-exact` не даёт npm записать диапазон `^` в `package.json`. Оба пакета в команде установки указаны точно, поэтому после установки npm создаёт lockfile.

Создайте в редакторе `tsconfig.json`:

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "Bundler",
    "strict": true,
    "skipLibCheck": true,
    "resolveJsonModule": true,
    "noEmit": true
  },
  "include": ["src"]
}
```

И временный `src/demo.ts`, достаточный для проверки запуска:

```ts
const message: string = "TypeScript запускается";
console.log(message);
```

Проверьте:

```sh
npm run check
npm run demo
```

Команды одинаковы в Linux и Windows PowerShell. После того как `package-lock.json` появился, на новой чистой копии используйте `npm ci`; эта команда читает lockfile и не выбирает новые версии. Не запускайте её в пустом `trainer/` до `npm init` и установки зависимостей.

## Как читать манифест проекта

В `package.json` обычно находятся:

```json
{
  "private": true,
  "type": "module",
  "scripts": {
    "check": "tsc --noEmit",
    "demo": "tsx src/demo.ts"
  }
}
```

Это инфраструктурный фрагмент, а не решение A1. Команда `npm run check` берётся из `scripts` и вызывает локальную версию `tsc` из `node_modules/.bin`; `npm run demo` передаёт путь к файлу инструменту `tsx`. `package-lock.json` и `node_modules/` создаются установкой: первый хранит воспроизводимость, второй — рабочие копии пакетов. `node_modules/` не добавляйте в Git.

## Модель данных без привязки к экрану

Начинайте с вопросов к контракту: какие поля общие, какая форма имеет дополнительные поля, какое поле различает варианты, как сущности связываются между коллекциями. Discriminated union — это несколько форм с общим полем-отличителем. Например, для каталога книг можно разделить бумажную книгу с `pages` и аудиокнигу с `duration`; после проверки `kind` TypeScript разрешает соответствующее поле.

```ts
type PaperBook = { id: string; kind: "paper"; pages: number };
type AudioBook = { id: string; kind: "audio"; duration: number };
type LibraryItem = PaperBook | AudioBook;
```

Это пример другой предметной области. В A1 перенесите тот же принцип на формы `Task` и `Answer` из [контракта](../../../course/CONTRACT.md), но названия и состав своих типов проверьте по требованиям задания. Не превращайте `topic` в закрытый union только потому, что в опубликованном примере сейчас несколько тем.

### Импорт, экспорт и аннотации

Модули связываются через `export` и `import`. Небольшой пример каталога заметок показывает optional-поле и типы параметров, но не задаёт алгоритм A1.

`catalog.ts`:

```ts
export type Note = {
  id: string;
  title: string;
  subtitle?: string;
};

export function titleWithPrefix(note: Note, prefix: string): string {
  return `${prefix}: ${note.title}`;
}
```

`preview.ts`:

```ts
import type { Note } from "./catalog";
import { titleWithPrefix } from "./catalog";

const note: Note = { id: "n-1", title: "Идея" };
console.log(titleWithPrefix(note, "Заметка"));
```

В конфигурации `ESNext` + `Bundler` такой импорт без расширения согласован с `tsx` и будущим Vite. Аннотация `subtitle?: string` означает, что поле может отсутствовать; это не разрешает произвольные дополнительные поля.

## Коллекции и результаты

`find` отвечает на вопрос «какой первый элемент подходит?» и возвращает элемент или `undefined`. Поэтому вызывающий код должен иметь ветку отсутствия. `filter` отвечает на вопрос «какие элементы подходят?» и всегда возвращает массив, в том числе пустой. Оба метода не должны менять исходную коллекцию.

```ts
const books: PaperBook[] = [
  { id: "b-1", kind: "paper", pages: 120 },
  { id: "b-2", kind: "paper", pages: 240 },
];

const found = books.find((book) => book.id === "b-1");
const short = books.filter((book) => book.pages < 200);
```

Фрагмент показывает форму результата и не является алгоритмом A1. В собственной реализации выберите имена функций, сигнатуры и способ подсчёта сами. Зафиксируйте в `demo.ts`, как функция ведёт себя при отсутствии результата и пустом массиве.

## Производное значение и чистота

Прогресс — производное значение: оно получается из набора и ответов, а не хранится как второй независимый источник. Для текста важно различать строку, состоящую только из внешних пробелов, и непустой текст; `trim()` возвращает новую строку и не меняет исходную.

Проверяемые случаи A1 включают пустой набор, один ответ, полный набор и ответ с чужим `taskId`. Не оценивайте правильность ответа и не проверяйте внешний JSON в A1: входные литералы задания считаются корректными по форме.

Чистая функция:

- получает всё необходимое через параметры;
- возвращает результат вместо изменения внешней переменной;
- не вызывает React, HTTP, `localStorage`, случайность или часы;
- не мутирует переданные массивы и объекты.

Критерий A1: вызовы функций не мутируют переданные наборы, ответы и вложенные объекты.

## Демонстрация и границы

Оставьте в `src/domain.ts` только свои типы и функции, а в `src/demo.ts` — типизированные входы и вывод результатов. Возьмите из JSON задания `ts-1` и `react-1` со всеми полями, добавьте второй набор с другими id и темой, пустой набор и требуемые сценарии. Импорт JSON можно использовать для просмотра формы, но безусловное `as` не превращает внешний вход в проверенный объект.

До следующего этапа не добавляйте React, Vite, формы, HTTP или сохранение. Строка `code` является данными для будущего `<pre>`, а не программой для исполнения.
