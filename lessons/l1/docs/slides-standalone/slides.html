Проверка запуска

npm run check npm run demo
  • check проверяет типы.
  • demo запускает маленький .ts-файл.
  • npm ci используется после создания lockfile.

Команды одинаковы в Linux и Windows PowerShell.

Модель — это договорённость

Спросите: какие поля общие? Что различает формы? Какие поля появляются только в одном варианте? Как две коллекции связаны id?

PaperBook | AudioBook ↓ kind доступное поле формы

Discriminated union

type PaperBook = { id: string; kind: "paper"; pages: number; }; type AudioBook = { id: string; kind: "audio"; duration: number; };

Проверка kind помогает безопасно выбрать соответствующее поле.

Коллекции

find

Один элемент или undefined; отсутствие нужно обработать.

filter

Новый массив, возможно пустой; исходные данные не меняются.

Пустой результат — обычный результат, а не исключение.

Производное значение

Прогресс вычисляется из набора и ответов. Число заполненных элементов не должно жить вторым независимым состоянием.

  • выбор считается заполненным;
  • текст из внешних пробелов — нет;
  • чужой идентификатор — не относится к текущему заданию.

Чистая функция

  • получает всё нужное через параметры;
  • возвращает значение;
  • не мутирует массивы и объекты;
  • не зависит от React, HTTP, часов и случайности.

В demo.ts покажите результаты вызовов для обычных и пустых входов.

A1: самостоятельная работа

  • Описать две формы заданий и две формы ответов по контракту.
  • Реализовать поиск по id, фильтр по теме и прогресс.
  • Проверить обычные и пустые наборы, отсутствующий id, чужой id и пробелы.
  • Создать типизированные данные из опубликованного примера и второй набор.
  • Запустить check и демонстрационный файл.
