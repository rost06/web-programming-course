# L1. TypeScript и данные тренажёра

## Зачем эта тема

На L0 вы собрали страницу портфолио из HTML, CSS и JavaScript. Теперь начинается отдельный проект `trainer`: его нужно создать самостоятельно и постепенно развивать до приложения тренажёра. TypeScript помогает описать форму данных и заметить несогласованность до запуска. Это особенно полезно, когда один набор заданий используется несколькими экранами.

Термины, которые понадобятся:

- **TypeScript** — JavaScript с проверяемыми типами; он проверяет исходный код до запуска, но сам по себе не проверяет внешний JSON.
- **тип** — описание допустимой формы значения;
- **объект** — значение с именованными полями;
- **массив** — упорядоченная коллекция значений;
- **union** — тип «один из нескольких вариантов»;
- **функция** — именованное действие с входами и результатом;
- **чистая функция** — функция без скрытого состояния и изменения входных данных.

## Подготовьте свой проект

В репозитории `trainer/` содержит только навигатор и `.gitignore`. Откройте эту существующую папку и создайте проект и исходные файлы внутри неё; портфолио L0 остаётся в `lessons/l0/`. Длинная последовательность команд, минимальный `tsconfig.json` и объяснение lockfile находятся в [гайде](docs/GUIDE.md).

На L1 вам нужно самостоятельно создать `package.json`, `package-lock.json`, `tsconfig.json`, `src/domain.ts` и `src/demo.ts`, настроить scripts `check` и `demo`, установить точные версии TypeScript и инструмента запуска, а затем выполнить `npm run check` и `npm run demo`. До создания своего проекта команда `npm ci` в `trainer/` не используется.

## Задание A1

В созданном проекте опишите типизированное ядро тренажёра и покажите его работу в `src/demo.ts`. Материалы задают контракт и проверки, а алгоритм и имена функций выберите самостоятельно.

### Данные и типы

Используйте [контракт курса](../../course/CONTRACT.md) и [опубликованный JSON](../../course/data/training-set.json). Опишите:

- `TrainingSet` с `id`, `title` и `tasks`;
- две формы `Task`, различающиеся по `kind`: `single-choice` с `options` и `short-text` без `options`;
- две соответствующие формы `Answer`, связанные с `taskId`.

В `src/demo.ts` создайте небольшие типизированные литералы: возьмите задания `ts-1` и `react-1` из JSON и сохраните все их поля, включая необязательное `code`, если оно есть. Добавьте массив ответов, второй набор с другими идентификаторами и темой, а также пустой набор. Импорт JSON с безусловным приведением типа не заменяет типизированные литералы.

### Функции и сценарии

Реализуйте три чистые функции с выбранными вами именами и типами результатов:

1. поиск задания по `id`;
2. фильтрация заданий по произвольной строке `topic`;
3. подсчёт прогресса как числа заполненных ответов и общего числа заданий.

Проверьте поиск существующих и отсутствующего идентификаторов: для отсутствующего задания результат — `undefined`, без необработанной ошибки. Проверьте фильтр с совпадениями и без них, пустые входы, один ответ и полный набор. Для пустого набора прогресс равен `0` из `0`. Ответ с другим `taskId` не должен засчитываться для текущего задания. Для `short-text` строка из пробелов не заполнена; правильность ответа в A1 не оценивается.

Покажите в `demo.ts`, что функции не изменили исходный набор и массив ответов. Входы задания считаются корректными по форме: идентификаторы заданий уникальны, на один `taskId` приходится не более одного ответа, а для существующего задания `kind` ответа совпадает с `kind` задания; у существующего `single-choice` `optionId` выбран из его списка `options`. Ответ с неизвестным `taskId` допустим и не влияет на прогресс. Проверять повреждённые внешние объекты, дубликаты или неизвестные варианты в A1 не требуется.

### Границы этапа

React, Vite, HTTP, `localStorage`, формы и тестовый раннер появятся позже. Строка `code` из набора — текст для будущего отображения, её нельзя исполнять.

**Вопросы:** Что возвращает поиск отсутствующего id? Почему связь ответа строится через `taskId`, а не позицию? Что считается заполненным текстовым ответом? Чем compile-time-проверка отличается от проверки JSON во время выполнения?

## Проверка и сдача

Из `trainer/`, одинаково в Linux и Windows PowerShell:

```sh
npm run check
npm run demo
```

Сдайте ветку с изменениями `trainer/`, приложите SHA и коротко опишите сценарии проверки. A1 проверяется на P2; работа L0 остаётся отдельным портфолио и проверяется по своему маршруту.

## Критерии зачёта

- проект и зависимости созданы студентом с точными версиями и lockfile;
- `check` и запуск демонстрационного `.ts`-файла проходят;
- типы различают обе формы заданий и ответов;
- поиск, фильтр и прогресс работают на обычных, пустых и изменённых наборах;
- отсутствующий id и пробельный текст обработаны безопасно;
- функции не мутируют входы и не используют индекс как идентификатор;
- решение A1 написано самостоятельно по опубликованному контракту.
