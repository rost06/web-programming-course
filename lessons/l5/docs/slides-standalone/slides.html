HTTP: путь ответа

От поля формы к подтверждённой попытке и результату сервера.

Зачем нужен сервер

  • локальное поле — намерение пользователя;
  • Attempt — подтверждённое состояние;
  • Result — решение сервера.

Что такое запрос

Метод, URL, заголовки и тело. Ответ содержит статус, заголовки и тело.

const response = await fetch(url);
if (!response.ok) throw new Error(String(response.status));

Promise и fetch

Ошибка сети отклоняет Promise. HTTP 400/500 требуют явной проверки response.ok.

JSON без лишних полей

{"taskId":"ts-1","kind":"single-choice","optionId":"b"}

Идентификатор задания, вид ответа и значение из контракта.

PUT сохраняет ответ

Повторный PUT для taskId заменяет ответ. Позиция на экране не является идентификатором.

DELETE очищает ответ

Повторное удаление допустимо. Это отдельное действие, а не пустой Answer.

Жизненный цикл Attempt

POST создать → PUT сохранить → GET прочитать → POST submit → GET result.

Submit закрывает редактирование

После submitted изменения получают 409. Повторный submit возвращает тот же результат.

Result не равен локальному счёту

pending-review и score: null нужно показать явно. Клиент не подменяет оценивание.

Ошибка — часть интерфейса

Оставить ввод, показать причину, дать повтор. Не очищать поле в catch.

Network как доказательство

Проверяем метод, URL, payload, статус и response.

Контракт A5

GET set, POST attempt, PUT/DELETE answer, POST submit, GET result.

Демонстрация

GET → PUT → повтор PUT → X-Demo-Fail: 1 → повтор без заголовка.
