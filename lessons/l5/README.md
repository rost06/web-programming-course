# L5. HTTP: отправка работы и ответ сервера

## Задание A5

Развивайте один и тот же тренажёр. Подключите его к предоставленному учебному API через браузерный `fetch`. A5 сдаётся на следующей практике, P6. На P5 проверяется A4 — черновик и восстановление; требования этой лекции не становятся критериями P5.

## Результат

Пользователь должен загрузить набор, создать попытку, сохранять каждый ответ, видеть подтверждение сервера, отправить попытку и получить результат или статус `pending-review`. Локальный ввод не исчезает из-за сетевой ошибки; во время запроса кнопка недоступна, повтор выполняется явно.

## Контракт

Используйте только [контракт API](../../course/CONTRACT.md). Ответы: `{taskId,kind,optionId}` для `single-choice` и `{taskId,kind,text}` для `short-text`. Не заменяйте `taskId` индексом и не добавляйте клиентские поля с оценкой.

Из корня репозитория запустите учебный сервер:

```sh
node course/server/server.mjs
```

Команда одинакова в Linux и Windows PowerShell. Сервер доступен по адресу `http://localhost:3001`. Команду запуска клиента берите из README вашей текущей рабочей версии `trainer`; не добавляйте новую команду только для A5.

## Обязательные сценарии

- отображаются данные набора из API;
- для обоих видов заданий отправляется корректный Answer;
- PUT заменяет ответ того же `taskId`, DELETE очищает его;
- submit отправляет `{}` и закрывает редактирование;
- `null` отображается как ожидание проверки, а не как ноль;
- HTTP-ошибка или отсутствие соединения видны пользователю, ответ остаётся на экране, есть повтор;
- при работающем сервере перезагрузка позволяет прочитать подтверждённую попытку;
- Network показывает реальные запросы к API.

## Критерии сдачи

- загрузка набора и создание попытки;
- правильные PUT/DELETE для ответов обоих видов;
- submit/result и состояния `submitted`/`pending-review`;
- ошибки, повтор и блокировка кнопки;
- описание границы локального и серверного состояния.

Принимаются выполненные сценарии и объяснение реализации. Замечания фиксируются как конкретные доработки. Серверный результат нельзя вычислять и отправлять из клиента как собственный.

## Формат сдачи

Откройте PR из своей рабочей ветки приложения. Укажите SHA, команды запуска клиента и сервера и один проверенный сценарий ошибки. Не перемещайте приложение по папкам.

## Ограничения

Backend, OAuth, React Query, кодогенерация и облачный deploy не требуются. Учебный сервер хранит попытки в памяти: перезапуск удаляет попытки.
