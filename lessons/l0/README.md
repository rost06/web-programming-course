# Нулевое занятие: знакомство и стартовая практика

## Цель занятия

Попробовать собрать небольшую веб-страницу и подготовить рабочее окружение. Эта работа поможет понять, с чего лучше начать и каким темам потребуется больше внимания.

На этом занятии мы не начинаем TypeScript. К нему перейдём после вводного занятия.

## Термины и зачем они нужны

- **HTML** задаёт структуру и смысл страницы: заголовки, разделы, ссылки и изображения.
- **CSS** отвечает за внешний вид, расположение и читаемость на разных экранах.
- **JavaScript** добавляет поведение: реакцию на клик, ввод и другие события.
- **Node.js** запускает JavaScript-инструменты вне браузера. На L1 он понадобится для TypeScript-проекта.
- **npm** устанавливает и запускает пакеты проекта. Для L0 он не нужен, но его проверка сейчас подготовит переход к L1.
- **Редактор** показывает структуру файлов и помогает находить ошибки до запуска.
- **Git** сохраняет историю изменений, чтобы работу можно было проверить и вернуть предыдущую версию.

Сначала проверьте, что инструменты доступны, а затем работайте с портфолио. Эта проверка не создаёт клиент тренажёра и не заменяет задание L0.

## Установка и проверка окружения

Установите Node.js версии 24 или новее с [официальной страницы Node.js](https://nodejs.org/en/download/), редактор (например, [Visual Studio Code](https://code.visualstudio.com/download)) и Git с [официальной страницы Git](https://git-scm.com/downloads). На Linux можно использовать пакетный менеджер дистрибутива, если он предоставляет нужную версию Node.js; в Windows PowerShell подойдут официальные установщики или `winget`.

Команды проверки одинаковы в Linux и Windows PowerShell. Выполните их после установки:

~~~sh
node --version
npm --version
git --version
code --version
~~~

Команда `code --version` может быть недоступна, если редактор не добавил CLI-команду в PATH. В таком случае откройте редактор через меню системы и убедитесь, что он умеет открыть папку курса. Для Git при необходимости настройте автора коммитов:

~~~sh
git config --global user.name "Имя Фамилия"
git config --global user.email "your.email@example.com"
~~~

Эти команды одинаковы в Linux и Windows PowerShell. Если `node --version` показывает версию ниже 24 или одна из команд не найдена, исправьте установку до начала L1. Папку `trainer/` на L0 создавать не требуется.

## Формат и время

Лекция длится 90 минут: 15–20 минут занимает организация, проверка инфраструктуры и подключение к материалам, около 55 минут — содержательная часть, остальное — вопросы, обсуждение и выдача задания. Лекция проводится для двух групп.

После лекции выдаётся практическое задание. Студенты выполняют его самостоятельно и сдают к следующей встрече через 1-2 недели.

Практические занятия проходят двумя парами, с одной группой. Основная задача — проверить результаты, разобрать типовые ошибки, ответить на вопросы и при необходимости помочь исправить работу.

Сегодняшняя встреча ознакомительная, поэтому проверка предыдущей работы не требуется. Достаточно открыть материалы, понять задание и убедиться, что окружение запускается.

## Что подготовить

- установленный браузер Chrome, Firefox или Edge;
- редактор кода, например VS Code;
- Git;
- доступ к репозиторию курса;
- папку lessons/l0 на компьютере.

Дополнительные библиотеки и облачный деплой для стартовой работы не нужны.

## Стартовое задание: портфолио фотографа

Создайте одностраничный сайт-портфолио фотографа Анны Аннушкиной. Она занимается портретной и свадебной съёмкой, а также снимает природу.

В папке уже есть изображения и стартовая структура:

~~~text
lessons/l0/
├── index.html
├── css/style.css
├── js/script.js
└── images/
    ├── about.jpeg
    ├── nature_1.jpg
    ├── nature_2.jpg
    ├── portrait_1.jpg
    ├── portrait_2.jpg
    ├── wedding_1.jpg
    └── wedding_2.jpg
~~~

Сначала попробуйте самостоятельно наметить структуру и собрать первый вариант по требованиям. Основной маршрут по заданию — [гайд](docs/GUIDE.md), [краткая справка](docs/CHEATSHEET.md) и [интерактивные примеры](docs/interactive.html).

Если используете пример, адаптируйте его под портфолио: замените тексты, идентификаторы и пути к изображениям. Важно понимать назначение взятого блока и уметь объяснить свои изменения; при этом не требуется печатать каждый тег с нуля.

Расширенные тематические материалы перечислены в разделе [Расширенный справочник](#расширенный-справочник). Их не требуется читать целиком: открывайте нужный раздел по мере работы.

В [дизайн-спецификации](docs/photographer-portfolio-design-specs.html) приведён визуальный ориентир. Она не заменяет требования задания: оценивается прежде всего рабочий результат и понятность кода.

### Минимальный результат

- заголовок с именем фотографа;
- краткое описание услуг;
- навигация по основным разделам;
- галерея из шести локальных изображений;
- контактная информация;
- осмысленная HTML-структура без единого блока, собранного только из div.

### Базовый результат

- аккуратные цвета, шрифты, отступы и размеры;
- раскладка галереи через Flexbox или Grid;
- адаптация для узкого экрана;
- понятные состояния наведения для ссылок или карточек.

### Дополнительный результат

- увеличение изображения или простая модальная галерея;
- фильтрация фотографий по категории;
- форма обратной связи с базовой проверкой полей;
- плавная прокрутка к разделам.

Дополнительные пункты не обязательны. Если базовая версия не готова, сначала завершите минимальный результат.

## Порядок работы

### Сегодня после лекции

1. Откройте папку нулевого занятия и прочитайте это задание.
2. Просмотрите index.html, css/style.css, js/script.js и папку images.
3. Откройте стартовую страницу в браузере.
4. Запишите вопросы и определите разделы будущей страницы.

### До следующей встречи

1. Определите разделы страницы и наметьте их в index.html.
2. Соберите первый вариант HTML самостоятельно.
3. Добавьте обязательные разделы и шесть локальных изображений.
4. Добавьте базовые стили в css/style.css.
5. При желании добавьте поведение в js/script.js.
6. Проверьте страницу в браузере и в режиме адаптивного просмотра.
7. Откройте DevTools и исправьте ошибки во вкладке Console.
8. Сохраните и сдайте результат по инструкции преподавателя к следующей встрече.

### На практических занятиях

На двух практических парах преподаватель проверит сданные результаты, разберёт типовые ошибки и ответит на вопросы. Подготовьте работающий результат и коротко объясните:

- что вы успели сделать;
- какое решение считаете главным;
- где возникло затруднение;
- какой вопрос нужно разобрать.

Для этой работы локальный сервер не требуется. Откройте `lessons/l0/index.html` двойным щелчком или перетащите файл в браузер: страница использует только локальные HTML, CSS, JavaScript и изображения.

Результат этой стартовой практики — портфолио в `lessons/l0/`. Не переносите его в `trainer/`: на L1 там будет создан отдельный TypeScript-проект.

## Работа с Git

Команды одинаковы в Linux, macOS и PowerShell:

~~~bash
git status
git add lessons/l0/index.html lessons/l0/css/style.css lessons/l0/js/script.js
git commit -m "Complete lesson 0 portfolio"
~~~

Подробный порядок работы с fork, веткой, commit, push и pull request описан в [гайде по Git и GitHub](../../docs/GITHUB_GUIDE.md). Отправляйте работу через pull request по этой инструкции и требованиям преподавателя.

## Чекпоинты

### Чекпоинт 1. Окружение и план страницы

После ознакомления с заданием назовите разделы, которые собираетесь сделать, и убедитесь, что стартовая страница открывается.

**Вопросы:**

1. Какой файл отвечает за структуру страницы?
2. Где будут находиться стили?
3. Как проверить ошибки JavaScript в браузере?

**Ожидаемые короткие ответы:** index.html; css/style.css; вкладка Console в DevTools.

### Чекпоинт 2. Минимальная страница

Перед сдачей проверьте заголовок, навигацию, описание, галерею и контакты.

**Вопросы:**

1. Какие элементы страницы должны быть доступны через навигацию?
2. Как подключены изображения из папки проекта?
3. Что изменится на странице при отключении файла CSS?

**Ожидаемые короткие ответы:** основные разделы; относительными путями; останется HTML-структура без оформления.

### Чекпоинт 3. Итоговая проверка

Откройте страницу на широком и узком экране, сохраните результат и подготовьте короткое объяснение для практического занятия.

**Вопросы:**

1. Какой результат вы считаете минимально готовым?
2. Какой элемент вы добавили сверх минимума?
3. Что осталось незавершённым и почему?

**Ожидаемые короткие ответы:** рабочая страница с обязательными разделами; конкретное дополнительное улучшение; честное описание ограничения.

## На что обратим внимание

Преподаватель смотрит на:

- самостоятельность и скорость ориентации в файлах;
- понимание базовой HTML-структуры;
- способность связать CSS с элементами страницы;
- работу с путями к изображениям;
- умение найти и объяснить ошибку;
- качество вопросов, которые студент задаёт по ходу работы.

Это стартовая работа: незавершённый дополнительный пункт не является проблемой, если студент может объяснить, что успел сделать и где остановился.

## Что будет на практических занятиях

На практических занятиях мы не начинаем новую тему поверх незаконченной работы. Сначала проверяем сданные результаты, затем разбираем повторяющиеся ошибки и отвечаем на вопросы. Если работа не завершена, студент показывает текущий результат и формулирует следующий шаг.
