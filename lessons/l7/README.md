## A7. Исправление и объяснение решения

Продолжите свой проект в `trainer`. Срок — первая практика следующего полугодия, по опубликованному расписанию. Это переходное задание, для него обычный двухнедельный срок не применяется.

### Проверка 1. Путь одного ответа

Опишите в README своего проекта путь ответа: пользовательский ввод, состояние, запрос, подтверждение сервера, отображение результата. Назовите реальные файлы или функции своей реализации. Достаточно небольшой схемы и пояснений. Укажите, где остаются данные при ошибке отправки.

**Вопросы:** Где впервые появляется ответ? В какой момент его можно считать сохранённым сервером? Как результат попадает на экран?

### Проверка 2. Воспроизводимый дефект

Выберите замечание по A6 или воспроизведённый самостоятельно дефект. Зафиксируйте входные данные, действия, ожидаемый и фактический результат. Исправьте причину. Если дефектов не найдено, исследуйте один пограничный сценарий: опишите проведённую проверку и её результат, не придумывайте неисправность.

**Вопросы:** Какие действия воспроизводят проблему? Какое наблюдение указывает на причину? Как подтверждено исправление?

### Проверка 3. Повторяемость

Добавьте или уточните проверку, которая обнаруживает этот дефект. Для сценария без найденной ошибки сохраните регрессионную проверку ожидаемого поведения. Выполните команды проверки типов, сборки и тестов из инструкции [окружения](../../trainer/README.md).

**Вопросы:** Какой результат ожидает проверка? Какое нарушение она обнаруживает? Что остаётся за её пределами?

## Результат и сдача

PR A7 содержит описание пути ответа, краткий разбор, исправления при их необходимости и проверку. Укажите коммит A6, от которого считаете изменения. Не требуется переписывать всё приложение, добавлять backend или новую библиотеку. Дополнительная функция не заменяет исправление замечаний.

Работа принимается, если описание соответствует коду, сценарий воспроизводится, вывод подтверждается наблюдениями, а проверка и запуск выполняются по инструкции.
