L6

Тестируем поведение

Vitest и React Testing Library помогают зафиксировать важные пользовательские правила.

Зачем тест

Один тест связывает сценарий, действие и наблюдаемый результат. Он отвечает на конкретный вопрос и переживает внутреннюю перестройку компонента.

Термины

Vitest — runner, RTL — пользовательские запросы к DOM, jsdom — тестовое окружение, mock — контролируемая граница, cleanup — очистка DOM.

Подключение

Зависимости и script test добавляются студентом в существующий проект trainer точными версиями. До L6 команда npm test не обязательна.

Не создавайте новый проект вместо накопленной версии.

Настройка Vitest и DOM

import { defineConfig } from "vitest/config";
import react from "@vitejs/plugin-react";

export default defineConfig({
  plugins: [react()],
  test: {
  environment: "jsdom",
  globals: false,
  setupFiles: "./src/test-setup.ts",
  },
});

В setup импортируйте afterEach и cleanup, затем вызовите afterEach(cleanup).

globals: false

Импортируйте describe, it/test и expect из Vitest в каждом файле. Явная очистка DOM нужна для независимости тестов.

Сценарий

Для списка покупок: ввод → «Добавить» → название видно. Для пустой строки ожидаем отказ. Предметная область примера не связана с тренажёром.

RTL

Используйте render, userEvent и screen. Ищите role/name или label, а не случайный CSS-класс.

Асинхронность

Ожидайте user.click, используйте findBy или waitFor для реального изменения. Произвольные задержки не объясняют ожидание.

Навигация

Ввести ответ → перейти назад → вперёд → увидеть прежнее значение по тому же идентификатору.

Ошибка

Контролируемая API-ошибка → сообщение видно → ввод сохранён → повтор доступен. Внешний сервер и интернет не нужны.

Разбор дефекта

Факт → гипотеза → проверка → исправление. Хороший тест заранее отвечает, какое нарушение он обнаружит.

A6 и P7

Добавьте тесты поведения, настройте cleanup при globals: false, запустите npm test и npm run build, затем объясните границы одного теста.
