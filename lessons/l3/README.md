# L3. Ответы, формы и прохождение попытки

## Что нужно сделать

В `trainer/` продолжите приложение из A2. Пользователь должен пройти локальную тренировочную попытку по набору заданий:

- выбрать вариант у `single-choice`;
- ввести ответ у `short-text`;
- переходить назад и вперёд без потери уже введённых ответов;
- видеть прогресс и список незаполненных заданий;
- пропускать задание, но получить предупреждение перед завершением;
- увидеть обзор ответов после локального завершения.

Это учебный локальный режим. Сервер, оценивание и `fetch` появятся позже. Не вычисляйте клиентскую оценку и не отправляйте ответы наружу.

## Ограничения контракта

Используйте `Task.id` как ключ ответа. Форматы ответов:

```ts
type Answer =
  | { taskId: string; kind: "single-choice"; optionId: string }
  | { taskId: string; kind: "short-text"; text: string };
```

Пробелы и пустая строка в `short-text` считаются незаполненным ответом. Текст из `Task.code` показывайте как текст, не исполняйте.

## Рекомендуемый маршрут

1. Опишите тип состояния попытки и типы событий формы.
2. Сделайте контролируемые `radio` и `textarea`.
3. Поднимите ответы на общий компонент экрана попытки.
4. Добавьте навигацию по индексам, вычисляемый прогресс и список пропусков.
5. Покажите подтверждение перед завершением и отдельный режим `submitted`.
6. Проверьте сценарии вручную на наборе из `course/data/training-set.json`.

## Сдача и критерии

A3 сдаётся до следующей собственной практики. На P4 проверяется именно эта работа, а P3 проверяет A2.

Зачётный сценарий: изменить ответ, пройти задания в другом порядке, вернуться к тексту, увидеть пересчитанный прогресс, завершить с пропуском и убедиться, что завершённую попытку нельзя редактировать без явного старта новой попытки.
