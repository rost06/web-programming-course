# Гайд L3: формы и состояние попытки

[Задание](../README.md) · [Гайд](GUIDE.md) · [Справка](CHEATSHEET.md) · [Интерактив](interactive.html) · [Слайды](slides-standalone/slides.html)

## Зачем это нужно

Форма тренажёра — это не набор независимых кнопок. Ответ должен переживать переходы между заданиями, а интерфейс должен в любой момент объяснять, сколько уже сделано и что осталось. Для этого ввод становится контролируемым: текущее значение хранится в состоянии React, а элемент формы получает его через `value` или `checked`.

## Контролируемое поле

```tsx
function NameField() {
  const [name, setName] = useState("");

  return (
    <label>
      Имя
      <input
        value={name}
        onChange={(event) => setName(event.target.value)}
      />
    </label>
  );
}
```

Событие сообщает новое значение, а setter обновляет состояние. Не читайте значение только из DOM при переходе: тогда легко потерять его или рассинхронизировать обзор.

## Два вида ответа

У вариантов ответа и текста разные данные, поэтому обработчики должны сохранять разные формы объектов:

```tsx
const choose = (taskId: string, optionId: string) => {
  setAnswers((previous) => [
    ...previous.filter((answer) => answer.taskId !== taskId),
    { taskId, kind: "single-choice", optionId },
  ]);
};
```

Для текста используйте то же правило «заменить ответ с этим `taskId`», но поле `text`. Такой подход не зависит от позиции задания на экране.

## Неизменяемое обновление

Не меняйте массив через `answers.push(...)`: React может не увидеть тот же объект массива. Создайте новый массив через `filter`, spread или `map`. При обновлении одного элемента сначала удалите старую запись с тем же id, затем добавьте новую.

## Подъём состояния

Компонент `AnswerField` знает, как отобразить поле, но не должен владеть всей попыткой. Родитель хранит `answers`, `currentIndex` и `status`, а дочернему компоненту передаёт значение и callback. Так навигация и обзор читают тот же источник данных.

## Производные значения

Прогресс не нужно хранить отдельным setter-ом. Его можно вычислить:

```ts
const answeredCount = tasks.reduce(
  (count, task) => count + (isAnswered(answers, task.id) ? 1 : 0),
  0,
);
const progress = `${answeredCount} из ${tasks.length}`;
```

`isAnswered` для текста применяет `answer.text.trim().length > 0`; для выбора проверяет наличие `optionId`. Если хранить и `answers`, и `answeredCount`, они могут разойтись.

## Навигация

`currentIndex` должен оставаться в пределах массива. Кнопки «Назад» и «Далее» меняют только индекс; ответ уже сохранён обработчиком поля. На последнем задании кнопка может называться «К обзору». Переход к обзору не означает серверную отправку.

## Завершение

Перед завершением найдите пропущенные задания и покажите их идентификаторы или номера. Предупреждение не должно стирать ответы. После подтверждения переведите состояние в `submitted`, замените форму обзором и отключите редактирование. Новую попытку начинайте отдельной кнопкой, которая явно очищает локальное состояние.

## Доступность и проверка

Связывайте `label` с полем, используйте настоящие `button`, `fieldset` и `legend`, а не кликабельные `div`. Проверьте клавиатурой: выбор радиокнопки, переход к следующему заданию, возврат и редактирование текста. Отдельно проверьте пустой и пробельный ответ.

## Небольшая самопроверка

- Можно ли открыть задание 3, ответить, перейти на 1 и вернуться на 3?
- Меняется ли прогресс после удаления текста до пробелов?
- Остаётся ли ответ в обзоре после завершения?
- Заблокировано ли редактирование до явного старта новой попытки?
