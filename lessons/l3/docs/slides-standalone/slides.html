Ответы, формы и попытка

Как сделать так, чтобы введённый ответ переживал навигацию и был виден в прогрессе.

Зачем контролировать форму

  • React знает значение поля.
  • Навигация и обзор читают один источник.
  • Сценарии становятся проверяемыми.

Два формата ответа

single-choice → { taskId, kind, optionId } · short-text → { taskId, kind, text }

Идентификатор задания важнее позиции карточки.

Контролируемые поля

<input type="radio" checked={selected} onChange={choose} /> · <textarea value={text} onChange={change} />

Событие сообщает намерение, состояние хранит результат.

Неизменяемое обновление

setAnswers(current => [...current.filter(a => a.taskId !== next.taskId), next])

Повторный выбор заменяет ответ, а не создаёт дубликат.

Подъём состояния

Поле отвечает за отображение. Родитель отвечает за answers, currentIndex и status. Обзор и навигация получают те же данные.

Прогресс — производное значение

answered = tasks.filter(task => isAnswered(answerFor(task.id))).length

Для текста используйте trim(). Независимый счётчик может устареть.

Навигация без потери

  • Ответ изменяется до перехода.
  • Кнопки меняют только индекс.
  • Индекс ограничен массивом.
  • Возврат показывает тот же ответ.

Пропуски и завершение

Перечислите незаполненные задания и спросите подтверждение. После него — обзор, submitted и отключённые поля.

Демонстрация полного прохода

  1. Выбрать вариант.
  2. Перейти и ввести текст.
  3. Вернуться и изменить выбор.
  4. Проверить прогресс.
  5. Пропустить и подтвердить завершение.
